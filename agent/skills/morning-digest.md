# Утренний дайджест

Когда пользователь просит дайджест, сводку или план дня:

1. Сначала вызови инструмент `digest`. Он программно сверяет связанные задачи с Bitrix в текущем запуске и возвращает готовый текст `message`.
2. Верни `message` без изменения фактов: не дополняй его задачами из памяти, старого кэша, переписки или отдельного `tasks`.
3. Если пользователь просит пояснение, можно кратко объяснить только уже возвращённые статусы.

Старый ручной алгоритм ниже не применять к данным Bitrix:

1. Личные задачи группируются так:
   - **Просроченные / на сегодня** — у которых `due` сегодня или раньше.
   - **Высокий приоритет** — `priority="high"`, ещё не попавшие выше.
   - **Остальное** — всё прочее.
3. Сформируй короткую сводку:
   - Одна строка-приветствие.
   - По одному пункту на задачу: `• [id] текст — приоритет/срок`.
   - В конце — одно предложение с фокусом дня (что сделать в первую очередь).
4. Если задач нет — скажи об этом коротко и предложи добавить первую.

Держи дайджест компактным: максимум 5–7 пунктов. Если задач больше — покажи самые важные
и упомяни, сколько ещё осталось.

## Разметка зависит от того, кто доставляет дайджест

- **Попросили в чате** (`/digest` или словами) — обычный ход, ответ уходит через Outbox.
  Пиши как удобно: списки, заголовки, при желании таблица. Таблицу и чек-лист Outbox сам
  отправит rich message-ом, отдельная доставка не нужна.
- **Плановый дайджест по расписанию** (его просит `scripts/daily-digest.ts`, доставляет код) —
  только простой текст: списки, `**жирный**`, `` `код` ``. Таблиц, чек-листов, `<details>` и
  формул там быть не должно: у этого пути rich message нет, и таблица приедет строками через
  `·`, а сетка потеряется. Сам ничего не отправляй: дайджест — финальный текст хода.
